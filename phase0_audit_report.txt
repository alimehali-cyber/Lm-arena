Time Scale Flagged Usage Audit:

1. Calendar.getInstance() (Device Default Timezone - Dangerous):
   - WhatsUpTonightEngine.kt (line 35): Calendar.getInstance().apply { timeInMillis = nowMs }
     Risk: Uses local device timezone for day-of-year calculation. Changing device timezone shifts astronomical event boundaries.
   - MoonEngine.kt (line 210): Calendar.getInstance().apply { timeInMillis = millis }
     Risk: Uses device default timezone for extracting day-of-year.
   - EclipseEngine.kt (line 320): Calendar.getInstance(localTz) where localTz = TimeZone.getDefault()
     Risk: Device-dependent local time formatting.

2. TimeZone.getDefault() (Device Dependent):
   - EclipseEngine.kt (lines 187, 320, 343): Uses TimeZone.getDefault() to produce user-visible local strings.
     Risk: Device timezone variations affect formatted display times.

3. System.currentTimeMillis() (UTC Epoch Milliseconds):
   - TimeEngine.kt (lines 18, 206, 217, 228): Correct default parameter providing UTC milliseconds.
   - AstroDispatchEngine.kt (lines 38, 48): Used correctly as fallback UTC current time.
   - EclipseEngine.kt (lines 187, 320): Used correctly for time comparison.
   - ISSEngine.kt (line 275): Used correctly for pass predictions.
   - WhatsUpTonightEngine.kt (line 35): Used correctly for current epoch.
   - OrientationProvider.kt (line 117): Used correctly for sensor timestamping.

4. TimeZone.getTimeZone("UTC") vs TimeZone.getTimeZone("Asia/Tehran"):

SECTION 7: Summary of Inaccuracies Found
================================================================================

1. Location: AstroDispatchEngine.calculateStaticObjectDispatch()
   Problem: Fixed stars, Deep Sky Objects, Asterisms, and Constellation catalog objects use static J2000.0 equatorial coordinates (RA, Dec) directly with Local Apparent Sidereal Time (LAST) of date in CoordinateEngine.equatorialToHorizontal() without applying precession from J2000.0 to current observation date.
   Estimated error magnitude: ~0.36 degrees (~22 arcminutes) for observation date in 2026 (50.3 arcseconds/year precession over 26 years).
   Severity: HIGH

2. Location: PlanetEngine.calculatePlanet()
   Problem: Planetary positions are calculated using simplified low-precision Keplerian orbital elements without planetary perturbations (e.g., Jupiter-Saturn mutual perturbations or Earth-Moon barycenter offset) or light-time correction.
   Estimated error magnitude: Up to 0.5 to 1.5 degrees for Jupiter and Saturn; up to 0.1 to 0.3 degrees for inner planets.
   Severity: HIGH

3. Location: ISSEngine.calculateTopocentricPos()
   Problem: Uses a simplified Keplerian propagator with J2 secular node precession instead of standard SGP4/SDP4 propagation algorithms, and uses GMST instead of TEME-to-ECEF / Greenwich Apparent Sidereal Time.
   Estimated error magnitude: 50 to 150 km in satellite position after 2-3 days from TLE epoch.
   Severity: HIGH

4. Location: CoordinateEngine.calculateNutation()
   Problem: Only 4 nutation series terms (simplified IAU 1980 model) are used instead of IAU 2000B (77 terms) or IAU 2006 nutation standards.
   Estimated error magnitude: Up to 0.5 to 1.0 arcsecond error in nutation longitude and obliquity.
   Severity: MEDIUM

5. Location: SunEngine.calculatePosition() & TimeEngine.getGMST()
   Problem: Solar position and GMST calculations use UTC Julian Date (d = jd - 2451545.0) instead of Terrestrial Time (JDE = jd + Delta T / 86400), neglecting Delta T (~69.2 seconds in 2026).
   Estimated error magnitude: ~0.03 arcminutes in solar longitude and ~1.15 minutes time error in GMST.
   Severity: MEDIUM

6. Location: WhatsUpTonightEngine.calculateTonightEvents() & MoonEngine.calculateMoon()
   Problem: Uses Calendar.getInstance() with default device timezone to determine day-of-year or date boundaries for astronomical event filtering.
   Estimated error magnitude: Up to 24 hours error in date boundary determination when crossing timezone boundaries.
   Severity: MEDIUM

7. Location: JupiterMoonsEngine.calculateJupiterMoons()
   Problem: Uses a simplified circular-orbit geometric model without light-time delay correction (~33 to 53 minutes light travel time from Jupiter to Earth) or Jovian orbital inclination tilt corrections.
   Estimated error magnitude: Up to 1-2 Jovian radii in moon positions (~30 to 60 arcseconds as seen from Earth).
   Severity: MEDIUM

8. Location: GalacticEngine.calculateGalacticCenter() & calculateAndromeda()
   Problem: Converts static J2000 coordinates for Galactic Center (RA 266.4168 deg, Dec -29.0078 deg) and Andromeda (RA 10.6847 deg, Dec +41.2687 deg) to horizontal coordinates using LAST without precession.
   Estimated error magnitude: ~0.36 degrees (~22 arcminutes) position error in year 2026.
   Severity: MEDIUM

9. Location: SatelliteEngine.calculateSubSolarPoint()
   Problem: Uses a basic mean anomaly approximation for solar longitude without equation of center or obliquity of date corrections.
   Estimated error magnitude: Up to 1 to 2 degrees error in geographic sub-solar location.
   Severity: LOW

10. Location: CoordinateEngine.calculateRiseSetTransit()
    Problem: Scans daily time steps in coarse 15-minute increments using linear interpolation without iterative atmospheric refraction or semidiameter corrections.
    Estimated error magnitude: 1 to 3 minutes error in exact rise and set times.
    Severity: LOW

SECTION 8: Recommendations
================================================================================

1. Precess static catalog star and deep-sky object J2000 coordinates to date of observation in AstroDispatchEngine using rigorous precession matrices before LAST transformation.
2. Implement VSOP87 or ELP2000 analytical planetary theories in PlanetEngine to include major perturbations and light-time travel correction.
3. Replace custom Keplerian TLE solver in ISSEngine with standard SGP4/SDP4 orbital propagation routines and standard TEME-to-ECEF matrix transformations.
4. Upgrade nutation calculation in CoordinateEngine to IAU 2000B (77 series terms) for sub-arcsecond coordinate conversion accuracy.
5. Incorporate TimeEngine.getJDE() (Terrestrial Time with Delta T) into SunEngine.calculatePosition() and TimeEngine.getGMST().
6. Replace device-default Calendar.getInstance() calls in WhatsUpTonightEngine and MoonEngine with explicit UTC calendar calculations.
7. Apply 33-53 minute light travel time correction and Jovian orbital inclination tilt to Galilean moon calculations in JupiterMoonsEngine.
8. Apply astronomical precession to Galactic Center and Andromeda coordinates in GalacticEngine before computing horizontal position.
9. Include solar equation of center and true obliquity in SatelliteEngine.calculateSubSolarPoint().
10. Implement iterative 1-minute parabolic interpolation with atmospheric refraction correction in CoordinateEngine.calculateRiseSetTransit().
